# Развёрнутая версия (P1)

> Подготовлено до старта соревнования (заготовка, раскрывается в README).
> Основание — п. 7.4 прежней редакции положения (19.09; в редакции 23.09 единой таблицы нет, см. `docs/hackathon-rules.md`), критерий «Воспроизводимость и готовность к развёртыванию» (20 баллов):
> «Развёрнутая версия является преимуществом, но не заменяет возможность запуска проекта из репозитория».

## Зачем и с каким приоритетом

- Локальный запуск из репозитория — **P0**. Деплой — **P1, первым среди P1** (раньше MCP): он упомянут в критерии оценки
  и даёт эксперту увидеть **живую работу AI без своего ключа** — это снимает подозрение в «имитации» (см. `docs/hackathon-rules.md`).
- Делается только после зелёного smoke. Лимит — **20 минут**; не уложились — откладываем и возвращаемся к README.
- У команды есть свой сервер и домен. Деплой = тот же `docker compose up`, что у эксперта, за уже работающим общим nginx с TLS.
  Отдельной «продовой» сборки, второго compose-файла и CI не делаем.

## Почему свой сервер, а не Vercel / PaaS

Положение не ограничивает, где развёрнута версия, и не сравнивает инфраструктуру команд: оценивается сам факт работающей
развёрнутой версии (п. 7.4 прежней редакции). Свой сервер — не преимущество в баллах, а просто самый дешёвый по времени путь для нашей архитектуры:

- Наш проект — **один Docker-контейнер** (FastAPI + статика + SQLite). На сервере это тот же `docker compose up`, что у эксперта:
  ноль платформенного кода, развёрнутая версия честно совпадает с тем, что в репозитории.
- **Vercel не подходит архитектурно:** это serverless-функции без постоянного диска (SQLite и загруженные файлы не живут),
  с лимитами на длительность запроса и размер тела — агент с несколькими вызовами модели в них упирается. Пришлось бы
  разделять фронтенд и бэкенд и писать `vercel.json` — конфиг ради платформы, а не ради кейса.
- **PaaS с поддержкой Dockerfile** (Render, Railway, Fly.io) ближе, но: бесплатные тарифы обычно усыпляют сервис при простое
  (эксперт увидит минуту холодного старта или таймаут), диск эфемерный, условия тарифов меняются — перед использованием проверить.
- **Главное препятствие для любого PaaS:** автодеплой требует установить GitHub-приложение в организацию, которой принадлежит
  репозиторий. Репозиторий создаёт платформа организаторов — прав администратора у нас, скорее всего, не будет.
  Серверу достаточно `git clone` по токену на чтение.

Решение: **основной вариант — свой сервер**; PaaS — только если сервер недоступен в день хакатона.

## На хакатоне (после зелёного smoke)

> **Проверено 23.09.2026, утро.** Тестовый деплой на сервере (одноразовое приложение той же архитектуры: Vite-сборка + FastAPI
> + статика, один контейнер `hack-app` в сети `platforms_default`): `docker compose up -d --build` с нуля — **33 секунды**,
> `/health` отвечает и по `127.0.0.1:8010`, и по `https://hack.aican.cloud`. Тест удалён, адрес снова отдаёт 502/504.
> Базовые образы `python:3.12-slim` и `node:22-slim` скачаны заново (прежние были удалены очисткой). `buildx` на сервере нет —
> в Dockerfile **не использовать** `RUN --mount=type=cache` и прочий BuildKit-синтаксис: классический сборщик его не поймёт.
>
> ⚠ **Сервер не может клонировать репозиторий:** он приватный, токена на сервере нет. Вариант без токена — отправить
> закоммиченное дерево прямо с ноутбука (ровно то, что в репозитории, без локальных файлов):
>
> ```bash
> git archive --format=tar HEAD | ssh unik 'rm -rf ~/hack && mkdir ~/hack && tar -x -C ~/hack'
> ssh unik 'cd ~/hack && echo GIT_SHA='"$(git rev-parse --short HEAD)"' > .deploy-sha'
> ```
> Дальше `.env`, `docker-compose.override.yml` и `docker compose up -d --build` — как ниже. Вариант с токеном: fine-grained
> токен только на чтение этого репозитория (если организация BAITC-Hacks разрешает такие токены).

```bash
ssh <сервер>
git clone <репозиторий> ~/hack && cd ~/hack        # по токену только на чтение; сервер ничего не пушит
cp .env.example .env                               # вписать APP_MODE=live и ключ — только здесь, на сервере
echo 'APP_PORT=127.0.0.1:8010' >> .env             # 8000 на сервере занят; наружу порт не открываем — ходит nginx по сети

cat > docker-compose.override.yml <<'YAML'         # только на сервере, в репозиторий не попадает
services:
  app:
    container_name: hack-app
    restart: unless-stopped
    mem_limit: 2g
    networks: [default, platforms]
networks:
  platforms:
    external: true
    name: platforms_default
YAML

docker compose up -d --build
curl -s http://127.0.0.1:8010/health && curl -s https://hack.aican.cloud/health
```

- `docker-compose.override.yml` Compose подхватывает сам. Он не меняет код, зависимости, данные и алгоритмы — только имя
  контейнера, сеть и лимит памяти на нашем сервере. Добавить `docker-compose.override.yml` в `.gitignore`.
- Проверить P0-сценарий по публичному адресу с телефона через мобильный интернет, а не из сети площадки.
- В README, в начале раздела про запуск: ссылка, пометка «развёрнута конкурсная версия, работает в живом режиме с ключом команды»,
  и оговорка, что запуск из репозитория описан ниже и от ссылки не зависит.
- `/health` отдаёт хеш коммита (переменная сборки) — так видно, что развёрнута именно конкурсная версия.

## После заморозки

- На сервере остаётся **ровно замороженный коммит**: `git fetch && git checkout <хеш> && docker compose up -d --build`.
  Никаких правок «только на сервере» — оценивается версия, зафиксированная в 18:00 (п. 5.4.13–5.4.14), расхождение выглядит как подмена.
- Сервер работает до конца Demo Day (29.09). Раз в день — проверка `/health` и остатка по ключу.
- Перезапуск после сбоя обеспечивает `restart: unless-stopped` из override-файла на сервере.

## Риски

| Риск | Что делаем |
| --- | --- |
| Публичная ссылка в README → чужой трафик тратит ключ | Лимит расходов на ключе; лимит размера запроса в nginx; без ключа приложение уходит в демо-режим, а не падает |
| Сервер недоступен в день проверки | Не критично: запуск из репозитория — основной путь; в README ссылка подана как дополнение |
| Данные пользователей на публичном сервере | В демо — только синтетические данные; загруженные файлы не храним дольше сессии, если кейс не требует |
| Наш контейнер мешает соседним проектам на сервере | Лимиты памяти и CPU в compose на сервере; не трогаем общий nginx сверх своего конфига |
| Деплой съел время P0 | Лимит 20 минут; делает один человек (Максим), остальные не отвлекаются |
