# Инструкция по подготовке README для жюри HackAlem AI

Основа — промпт из документации хакатона, предоставленный участником команды.
Ниже он сохранён без изменения формулировок; нормализованы только переносы строк.
Дополнительные уточнения команды вынесены отдельно и не являются частью исходного промпта организатора.

## Исходный промпт из документации хакатона

«Проанализируй текущий проект и создай для него полноценный README.md на русском языке.
README должен быть понятен жюри хакатона и содержать:

1. Название проекта
2. Краткое описание — какую проблему решает проект и для кого.
3. Что реализовано — основные функции и возможности решения.
4. Как работает решение — кратко опиши основной пользовательский сценарий от входных данных до результата.
5. Технологии — языки, фреймворки, библиотеки, AI-модели, API и внешние сервисы.
6. Архитектура проекта — основные компоненты и как они взаимодействуют.
7. Установка и запуск — пошаговая инструкция с необходимыми командами.
8. Как проверить решение — пример сценария, который может повторить жюри.
9. Данные и интеграции — какие источники данных, API или внешние сервисы используются.
10. Ограничения — что не реализовано или какие ограничения есть у текущей версии.
11. Ссылка на deployed-версию, если она существует.

Используй только информацию, которую можно подтвердить по текущему репозиторию. Не придумывай функции, технологии или результаты, которых в проекте нет. Оформи README аккуратно в Markdown.»

## Дополнительные уточнения команды

При необходимости следующий текст можно добавить после исходного промпта.
Он уточняет содержание его разделов, сохраняя все 11 пунктов. Сохранение их порядка — наш выбор для удобства сверки;
из приведённого текста организатора не следует требование дословно воспроизводить заголовки или порядок.

- Сохрани все 11 пунктов исходного промпта как отдельные разделы в указанном порядке. Если README уже существует, обнови его по фактической реализации и сохрани достоверное раскрытие заготовок и сторонних компонентов. Изменяй только README.md.
- Для конкретизации под кейс используй CASE.md и официальное ТЗ, доступные в репозитории. В разделах 1–2 укажи подтверждённые название задачи и трек, пользователя и решаемую проблему. Не выводи требования из одного названия трека. Если ТЗ отсутствует, сообщи об этом отдельно и не придумывай предметные сведения.
- В разделе 3 свяжи основные требования ТЗ с реализованными функциями и конкретными файлами кода. При необходимости используй компактную таблицу «Требование | Статус | Где реализовано | Как проверить». Отличай реализованное, частично реализованное и планы. В разделе 4 оставь короткий понятный сценарий «ввод → действия пользователя → результат».
- В разделе 7 укажи необходимые программы и версии, оболочку и рабочую папку для команд, переменные окружения без секретов, адрес приложения и признак готовности. В разделе 8 дай конкретный пример входа, шаги и ожидаемый результат. Объясни, как проверить ключевую функцию без личных аккаунтов участников. Проверка /health подтверждает запуск, но не выполнение пользовательского сценария.
- В разделах 5 и 9 объясни фактическую роль AI, источники данных и внешние зависимости. Отличай живой вызов модели, сохранённый ответ, синтетические данные и заглушки. Опиши ограничения этих режимов в разделе 10. Не выдавай наличие библиотеки или инфраструктурного модуля за готовую функцию. Не публикуй показатели качества и скорости без подтверждения.
- Сохрани раскрытие заранее подготовленных и сторонних материалов с источником и назначением, а также подтверждёнными сведениями о лицензиях. Его можно оформить подразделом раздела 9. При наличии других требований официального ТЗ и правил проекта учти их, не приписывая их исходному промпту.
- Проверь пути, ссылки и согласованность команд с репозиторием. Выполни доступные локальные проверки. В ответе отдельно от README перечисли, что реально проверено, что не удалось проверить и какие расхождения обнаружены. Не называй непроверенный запуск успешным.

Эти уточнения служат понятности и проверяемости README. Они не предполагают знания устройства AI-судьи и не содержат обращений к нему.
