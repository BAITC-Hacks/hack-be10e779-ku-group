Выполни процедуру «Заморозка» из `docs/playbook.md`. С этого момента (17:00) новые фичи и изменения архитектуры не пишем и не предлагаем.
Контрольные точки: 17:35 последний содержательный merge · 17:45 smoke · 17:50 финальный commit и push · 18:00 фиксация организатором
(п. 5.4.13), после неё ничего не учитывается и не принимается (п. 5.4.14, 5.4.16).

1. `git status` и `git log` — что не закоммичено и не запушено у этого участника.
2. Тесты и линт (`pytest -q`, `ruff check .`, сборка frontend). Упавшее — чинить или откатывать, не маскировать.
3. `/smoke` на чистом клоне. Расхождение с README исправляется в README или в коде сразу.
4. Пройди «Финальный чек-лист» из playbook: по каждому пункту — доказательство (команда, файл, строка), а не «вроде да».
5. Секреты: `git ls-files | grep -i env`; поиск характерных префиксов ключей в рабочем дереве и в истории
   (`git log -p -S'sk-'`). Ключ в истории — немедленно сказать человеку: ключ отзывается, историю не переписываем.
6. Раздел раскрытия в README сверь с фактическими `requirements.txt` и `package.json` — каждая зависимость названа.
7. Проверь, что демо-данные, сценарий показа и скриншоты для Demo Day лежат в репозитории.
8. Запиши хеш последнего рабочего коммита в `docs/progress.md`.
9. Итог — короткий список: готово / не готово / что успеваем исправить до 17:50. Финальный коммит и push — только после
   подтверждения человеком и не позднее 17:50; убедиться, что коммит виден на GitHub, и записать SHA в `docs/progress.md`.
