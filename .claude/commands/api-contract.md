Выполни процедуру «Контракт API» из `docs/playbook.md`.

1. Прочитай P0-сценарий и DoD в `CASE.md` и раздел «API» в `docs/architecture.md`.
2. На каждый шаг пользователя — эндпоинт под `/api/...`: метод, путь, тело запроса, ответ 200 с примером JSON
   на демо-данных, ошибки (`{"detail": "…"}` + HTTP-код), статусы длительных операций, если они есть.
3. Типы данных опиши один раз общим списком — из них получатся Pydantic-схемы и TS-типы.
4. Укажи, какие файлы демо-данных лежат в `data/demo/` и какой пример проходит весь сценарий.
5. Только эндпоинты P0. Ничего «на вырост».
6. Запиши `docs/api-contract.md`. Если файл уже существует и утверждён — **не меняй его**: опиши предлагаемую правку
   и напомни, что контракт утверждает Максим, а изменение задевает двух других участников.
7. В конце перечисли, что по этому контракту frontend может замокать прямо сейчас.
