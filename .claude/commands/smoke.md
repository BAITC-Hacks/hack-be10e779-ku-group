description: Smoke-проверка — запуск с нуля без ключей и проход основного сценария по README
---

Выполни процедуру «Smoke» из `docs/playbook.md`.

1. Сделай свежий клон текущего состояния во временную папку (не в рабочую директорию) — это чистое окружение эксперта.
   Дальше выполняй **только то, что написано в README, в том порядке, в каком написано**: `.env` — из `.env.example` без ключей
   и без личных аккаунтов (п. 5.6.6). Шаг, которого нет в README, — уже провал: по п. 5.4.16 проект, не запустившийся по README,
   не допускается, пояснения не принимаются.
2. Запуск командами из README (ожидаемо `docker compose up --build`); дождись `/health` = 200.
3. Пройди шаги из README, раздел «Проверка основного сценария», буквально так, как это сделал бы эксперт, который видит проект впервые. Через API — `curl`; UI — проверь, что страница отдаётся. Если README описывает тестовый доступ к внешнему сервису — проверь его тоже.
4. Проверь некорректный ввод: пустой, слишком большой, неверный тип файла — должна быть понятная ошибка, а не падение.
5. Просмотри логи контейнера: нет секретов и необработанных трассировок.
6. Проверь, что в репозитории нет `.env` и ключей (`git ls-files`, поиск по характерным префиксам ключей).
7. Итог — короткий список: что прошло, что нет, что расходится с README. Расхождения предложи исправить сразу.
8. Останови контейнеры и убери временную папку.
