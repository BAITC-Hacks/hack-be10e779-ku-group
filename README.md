# ВетроПрогноз — почасовой прогноз выработки ВЭС на 24–48 часов

Система строит ретроспективные прогнозы нормированной выработки ветроэлектростанции по двум турбинам. Для каждого выпуска она использует только архивные прогнозы погоды, которые уже были доступны на соответствующий момент времени, и формирует почасовые значения `p10`, `p50` и `p90` на двое суток вперёд.

## Назначение и что реализовано

Пользователь решения — диспетчер или аналитик ВЭС. Основной результат — воспроизводимый прогноз выработки станции и каждой турбины за февраль 2026 года с оценкой неопределённости и сравнением со свежестью предыдущего выпуска.

## Архитектура

Цикл повторяет обязательную последовательность из ТЗ:

```text
дата выпуска D
      │
      ▼
Open-Meteo Previous Runs
D+1 ← *_previous_day1
D+2 ← *_previous_day2
      │
      ▼
подготовка почасовых признаков и ансамбля погоды
      │
      ▼
квантильный градиентный бустинг
      │
      ├── p10 / p50 / p90 по станции
      ├── прогноз турбины 1 и турбины 2
      └── базовая эмпирическая кривая мощности
      │
      ▼
анализ правдоподобия и неопределённости
      │
      ▼
сравнение D+1 с прогнозом тех же часов из вчерашнего D+2
```

`backend/app/forecast/cli.py` последовательно воспроизводит выпуски с 31.01.2026 по 27.02.2026. Каждый выпуск содержит 24 часа D+1 и 24 часа D+2. Итоговый файл на февраль берёт для каждого часа наиболее свежий прогноз D+1.

## Технологии

- Python 3.12, pandas и NumPy — загрузка, агрегация и подготовка временных рядов.
- scikit-learn `HistGradientBoostingRegressor` — квантильные модели `p10`, `p50`, `p90` и модели отдельных турбин.
- Open-Meteo Previous Runs API — архивные выпуски прогноза погоды без ключа.
- FastAPI и Uvicorn — сервер приложения; SQLAlchemy и SQLite — подготовленный слой хранения.
- React, TypeScript и Vite — frontend-каркас.
- pytest и Ruff — тесты и статический контроль backend.
- Docker Compose — единый контейнер и один внешний порт.

## Данные

Организатор предоставил два CSV-файла: `data/raw/turbine1.csv` и `data/raw/turbine2.csv`. Они содержат 10-минутные измерения с 11.03.2023 по 31.01.2026: время, скорость ветра, нормированную активную мощность и температуру. В модели час считается полным только при наличии всех шести 10-минутных точек.

Выработка станции определена как среднее нормированной мощности двух турбин. Установленная мощность в МВт не дана, поэтому все прогнозы остаются в диапазоне 0–1. Фактической выработки за февраль 2026 года в исходных данных нет.

Архивные ответы погоды сохранены в `data/weather/`, поэтому стандартный бэктест и прогноз работают без сети. Обновление этих файлов — отдельная явная команда, требующая интернет-соединения.

## Источник погоды и защита от утечки

Используется [Open-Meteo Previous Runs API](https://open-meteo.com/en/docs/previous-runs-api) с лицензией [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Источник не требует ключа или личного аккаунта.

Поля `*_previous_day1` описывают прогноз на конкретный час из выпуска приблизительно за 24 часа до него, а `*_previous_day2` — приблизительно за 48 часов. Для выпуска в конце дня D система берёт:

- сутки D+1 только из `*_previous_day1`;
- сутки D+2 только из `*_previous_day2`.

Следовательно, оба набора были выпущены не позднее момента составления прогноза. Фактическая погода за прогнозируемые сутки и реанализ в признаках не используются. Это соответствие отдельно закреплено тестами в `backend/tests/test_forecast_core.py`.

## Установка

### Вариант 1: Docker

Нужны Docker 24+ и Docker Compose v2. Для первой сборки требуется интернет, чтобы скачать образы и зависимости.

```bash
git clone <URL репозитория>
cd <папка репозитория>
cp .env.example .env
docker compose up --build
```

### Вариант 2: локальный backend

Нужен Python 3.12.

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
```

Для локальной разработки frontend нужны Node.js 20+ и npm:

```bash
cd frontend
npm ci
```

## Запуск

Основной запуск всего приложения:

```bash
cp .env.example .env
docker compose up --build
```

После сборки технический endpoint доступен по адресу <http://localhost:8000/health>. Ожидаемый ответ содержит `"status":"ok"`. Если порт 8000 занят, задайте в `.env` другое значение `APP_PORT`, например `8080`.

Локальный запуск backend:

```bash
cd backend
.venv/bin/uvicorn app.main:app --reload --port 8000
```

## Воспроизведение бэктеста и метрик

Команды выполняются из каталога `backend` в подготовленном Python-окружении:

```bash
python -m app.forecast.cli backtest
python -m app.forecast.cli metrics
```

Первая команда создаёт полный ретроспективный прогон февраля. Вторая переобучает модель скользящим окном на четырёх отложенных месяцах — октябрь 2025, ноябрь 2025, декабрь 2025 и январь 2026 — и записывает результат в `outputs/metrics.json`. Для каждого месяца обучение заканчивается до его начала.

Чтобы заново получить архивные прогнозы из Open-Meteo, при наличии интернета выполните:

```bash
python -m app.forecast.cli weather
```

Эта команда не нужна для штатного воспроизведения: используемые ответы уже сохранены в репозитории.

## Метрики качества

Источник таблицы — `outputs/metrics.json`. Мощность нормирована в диапазоне 0–1; поэтому MAE и RMSE указаны в долях номинальной мощности. `nMAE` нормирован на среднюю фактическую выработку.

| Горизонт | Метод | Часов | MAE | RMSE | nMAE |
| --- | --- | ---: | ---: | ---: | ---: |
| D+1 | Бустинг и ансамбль погоды | 2885 | 0,1446 | 0,2155 | 0,4008 |
| D+1 | Кривая мощности | 2885 | 0,1783 | 0,2658 | 0,4942 |
| D+1 | Персистентность | 2846 | 0,3555 | 0,4750 | 0,9868 |
| D+2 | Бустинг и ансамбль погоды | 2885 | 0,1572 | 0,2323 | 0,4357 |
| D+2 | Кривая мощности | 2885 | 0,1905 | 0,2783 | 0,5280 |
| D+2 | Персистентность | 2826 | 0,3734 | 0,4895 | 1,0335 |

Покрытие интервала `p10–p90`: 0,692 для D+1 и 0,680 для D+2 при целевом уровне 0,80. Это известное ограничение, а не заявленная калиброванная вероятность.

## Надёжность и тесты

Тесты ядра проверяют отсутствие погодной утечки, правильное соответствие D+1/D+2, 48 почасовых значений, порядок квантилей, границы 0–1 и допустимый диапазон дат.

```bash
cd backend
.venv/bin/pytest -q tests/test_forecast_core.py
.venv/bin/ruff check .
```

Модель детерминирована (`random_state=0`). Квантили после прогнозирования принудительно упорядочиваются, а значения ограничиваются диапазоном 0–1. Пропуски погодных признаков интерполируются не более чем на три соседних часа.

## Известные ограничения

- Факт за февраль 2026 года организатором не предоставлен, поэтому качество за тестовый месяц нельзя вычислить локально.
- Выработка нормирована 0–1: без установленной мощности станции перевод в МВт невозможен.
- У турбины 1 есть крупный разрыв данных в мае–июле 2024 года; неполные часы исключаются из обучения.
- Покрытие интервала `p10–p90` ниже целевых 0,80; конформная калибровка пока не реализована.
- Исторический архив членов метеорологического ансамбля недоступен; используются отдельные глобальные модели через Previous Runs API.
- Прогноз рассчитан для фиксированных координат этой ВЭС и тестового периода 2026 года.
